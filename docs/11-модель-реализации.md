# Модель реализации

Как правила из предыдущих разделов превращены в работающий код. Этот документ
нужен, чтобы по нему можно было написать свою игру, не перечитывая исходники.

## Разделение на слои

```
data/               Данные: карты, способности, ассеты
  ├─ cards.json       154 карты со статами
  ├─ abilities.json   способности в исполняемом DSL
  └─ assets/          арты карт и иллюстрации

packages/
  ├─ shared/        Типы предметной области + загрузка данных
  ├─ engine/        Правила. Чистые функции, без ввода-вывода
  └─ ai/            Оппоненты. Работают поверх движка

apps/
  ├─ web/           Клиент. Движок и программный ИИ работают в браузере
  └─ server/        Раздача статики + прокси к нейросети
```

Ключевое решение: **движок не знает ни про интерфейс, ни про сеть**. Это один и
тот же код на клиенте и на сервере, поэтому локальная партия и серверный ИИ
не могут разойтись в трактовке правил.

## Модель состояния

```ts
GameState {
  players: [PlayerState, PlayerState]  // штаб, рука, колода, потери, взводы, ресурсы
  units:   UnitState[]                 // вся техника обоих игроков на поле
  current: 0 | 1                       // чей ход
  turn:    number
  rng:     { seed: number }            // генератор внутри состояния — партия воспроизводима
  winner:  0 | 1 | null
  log:     LogEntry[]
}
```

Почему **seed лежит внутри состояния**: без этого нельзя ни воспроизвести баг,
ни написать стабильный тест на раздачу, ни прогнать самоигру ИИ.
`Math.random()` в движке запрещён — используется `mulberry32` (`rng.ts`).

Координаты: `{ row: 0..2, col: 0..4 }`. Штаб игрока 0 — в `(2,0)`,
игрока 1 — в `(0,4)`. Плацдарм вычисляется как соседи своего штаба.

## Автомат хода

```
createGame
   ├─ перемешать обе колоды (по seed)
   ├─ раздать по 6 карт
   ├─ выбрать первого игрока случайно
   └─ beginTurn(первый ход = true)

beginTurn
   ├─ сбросить флаги своей техники (атака, запас хода, «выведен в этот ход»)
   ├─ сбросить контратаку у техники противника
   ├─ ресурсы := суммарный прирост      ← именно присвоение: остаток сгорает
   ├─ взять карту                        ← кроме первого хода первого игрока
   └─ сработать триггеры «в начале хода»

reduce(state, action)
   ├─ deploy / deploySquad / playOrder  — списать стоимость, разместить, сработать триггеры
   ├─ move                              — списать запас хода
   ├─ attack                            — разрешить бой (см. 02-бой.md)
   └─ endTurn
        ├─ сбросить лишние карты сверх шести
        ├─ триггеры «в конце хода»
        ├─ передать ход
        └─ beginTurn
```

`reduce` — чистая функция: входное состояние не изменяется, возвращается новое.

## Генератор легальных ходов

`getLegalActions(state, resolver)` — **единственный источник истины** о том,
что сейчас можно сделать. Им пользуются:

- интерфейс — для подсветки клеток и блокировки карт в руке;
- все программные оппоненты;
- режим нейросети — модель выбирает **номер** из этого списка.

Благодаря этому нелегальный ход невозможен ни в одном из режимов, а подсветка
в интерфейсе не может разойтись с правилами.

## DSL способностей

Способности на вики записаны обычным русским языком:
«Национальная особенность: Когда атакует — восстановите 2 прочности этому танку».
Чтобы движок мог их исполнять, текст переводится в декларативный JSON
(`tools/lib/abilities-dsl.mjs` → `data/abilities.json`):

```json
{
  "raw": "Национальная особенность: Когда атакует - восстановите 2 прочности этому танку.",
  "condition": { "hqNation": "germany" },
  "clauses": [
    { "op": "trigger", "on": "attack",
      "effects": [{ "op": "heal", "target": "self", "amount": 2 }] }
  ],
  "coverage": "full"
}
```

**Условие** (`condition`) — это зависимое свойство: карта работает только под
штабом нужной нации и/или типа. Проверяется в `conditionHolds` (`cards.ts`).

**Предложения** (`clauses`) бывают следующих видов:

| Операция | Смысл |
| --- | --- |
| `keyword` | Ключевое свойство: маскировка, охранение, прикрытие, арьергард, блиц, конвейер, подкрепления |
| `statBonus` | Постоянная прибавка к атаке, прочности, приросту, стоимости или поддержке |
| `costReduction` | Снижение стоимости за каждый объект на поле |
| `trigger` | Эффект по событию: `deploy`, `attack`, `counterattack`, `afterAttack`, `damaged`, `turnStart`, `turnEnd`, `enemyVehicleDestroyed`, `selfDestroyed`, `hqDealtDamageToEnemyHQ` |
| `onPlay` | Эффект в момент розыгрыша (так устроено большинство приказов) |
| `whileCondition` | Длящийся эффект при условии |
| `unparsed` | Не разобрано: движок игнорирует, текст сохранён |

**Эффекты** внутри триггеров: `damage`, `heal`, `draw`, `mill`,
`discardFromHand`, `recoverFromCasualties`, `gainResources`, `destroy`,
`grantKeyword`, `removeKeyword`, `bounce`, `spot`, `extraAttack`,
`bonusDamage`, `damageModifier`, `denyMove`, `denyCounterattack`.

### Покрытие: честные цифры

Из **253** строк способностей:

| Категория | Строк | Что это значит |
| --- | --- | --- |
| Исполняются полностью | **144** | Движок воспроизводит эффект целиком |
| Исполняются частично | **62** | Структура разобрана, часть условий осталась текстом |
| Пояснения, а не способности | **10** | Описание карты или пересказ общих правил |
| Не разобрано | **37** | Движок игнорирует; текст сохранён и показан в документации |

**Исполнимо от значимых строк: 84.8 %** (полностью — 59.3 %).

Полный список неразобранных способностей — в
[12. Источники](12-источники.md#способности-не-переведённые-в-исполняемый-вид).
Это преимущественно уникальные эффекты вроде «До конца хода противника все его
САУ и штаб не могут атаковать» — каждый требует отдельной операции DSL.

Карта с неразобранной способностью **не ломается**: она работает по своим
базовым характеристикам, просто без особого эффекта.

### Отдельно про честность оценки покрытия

Первая версия транслятора помечала способность как полностью исполнимую, если
сработало хотя бы одно правило. На карте «Feldmediziner» это давало опасный
результат: из эффекта «взвод уничтожается, штабу восстанавливается 6 прочности,
после этого возьмите карту» распознавалось только «возьмите карту», и способность
считалась полной. Сейчас транслятор считает **долю покрытого текста** и при
неполном разборе понижает оценку до частичной. Из-за этого число «полных»
способностей упало со 176 до 144 — цифра стала меньше, но перестала врать.

## Оппоненты

Все реализуют один интерфейс `Agent.chooseAction(state, data) → Action`
и выбирают ход только из `getLegalActions`.

| Уровень | Алгоритм |
| --- | --- |
| **Новобранец** | Случайный ход с отсевом явных самоубийств |
| **Сержант** | Жадная оценка на один полуход |
| **Офицер** | Поиск на несколько полуходов; ответ противника оценивается жадно |
| **Генерал** | Монте-Карло: каждый ход-кандидат прогоняется несколькими быстрыми партиями |
| **Нейросеть** | Модель выбирает номер хода из списка; движок проверяет и подстраховывает |

Оценочная функция (`evaluate.ts`) взвешивает прочность штабов, размен техникой,
взводы, руку, ресурсы и давление на штаб. Вес прочности вражеского штаба выше
своего — игра идёт на добивание, а не на выживание.

### Режим нейросети

```
Клиент ──POST /api/ai/move (состояние партии)──► Сервер
                                                   ├─ getLegalActions() — свой, серверный список
                                                   ├─ описать позицию словами
                                                   ├─ запрос к модели с инструментом choose_move
                                                   ├─ проверить номер: он обязан попасть в список
                                                   └─ при любом сбое — ход «Офицера»
Клиент ◄──────────── { action } ───────────────────┘
```

Три свойства этой схемы важны:

1. **Ключ API никогда не покидает сервер.** Клиент его не видит.
2. **Модель не может сходить не по правилам** — она выбирает из готового списка,
   а список строит движок на сервере, не доверяя присланному состоянию.
3. **Отказ модели не ломает партию.** Нет ключа, таймаут, лимит, мусор в ответе —
   ход делает программный ИИ, игрок видит уведомление.

## Что стоит сделать иначе в своей игре

Наблюдения по итогам реализации:

- **Прямая атака штаба по штабу без условий** делает партию гонкой на добивание
  и обесценивает позиционную игру. Если строите свою игру — стоит потребовать
  хотя бы обнаружения цели.
- **Сгорающие ресурсы** — сильное решение: они задают темп и наказывают за
  бездействие. Стоит сохранить.
- **Пять специализаций взводов, не отличающихся ничем, кроме имени**, —
  избыточная сущность. Ограничение «пять слотов» можно задать напрямую.
- **Свободный текст способностей** — источник половины трудозатрат этого проекта.
  В своей игре описывайте способности сразу в структурированном виде, а текст
  генерируйте из него, а не наоборот.
